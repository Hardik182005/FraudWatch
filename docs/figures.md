# Figures

Every figure in `docs/figures/` is generated by one script from committed artifacts or from a
command that was actually run. Nothing here is illustrative, smoothed, or invented.

```bash
python docs/figures/make_figures.py
```

The script has no dependencies beyond the Python standard library. It writes plain SVG with no
external fonts, no embedded raster data and no JavaScript, on a white ground — so the files are
safe to embed in a Markdown page, drop into a slide deck, or convert to PNG/PDF.

- Generator: [`docs/figures/make_figures.py`](figures/make_figures.py)
- Output directory: `docs/figures/`
- Regeneration is deterministic: same artifacts in, byte-identical SVG out.

## Provenance rules the generator follows

1. **Model figures are read, not recomputed.** The PR and ROC curves are the 200 points already
   stored in `evaluation.json`; the confusion counts, the sweep rows and the calibration bins are
   likewise read verbatim. The script does not re-score the model, so a figure can never disagree
   with the artifact it came from.
2. **Test-split numbers are never used to pick anything.** The threshold-sweep figure is drawn on
   the validation split, because that is where the alert and review thresholds were chosen.
3. **Accuracy is deliberately de-emphasised.** The PR figure carries a note explaining that
   always answering "not fraud" already scores about 96.5% on this split, so accuracy is not the
   metric to read.
4. **Amounts carry no currency.** `TransactionAmt` is in an undocumented source unit. No figure
   prints a currency symbol and none converts to any currency.
5. **Operational figures are labelled by how they were obtained.** The two CA2 figures say in the
   figure itself that they come from one run on one machine on one date, and they name the
   endpoints the values were read from.

## What these figures do NOT show — `_not measured yet_`

These are absent on purpose. Adding them requires running the harness in
[`docs/benchmark-methodology.md`](benchmark-methodology.md) and committing the output.

- **Throughput** (events/second sustained) for any engine — `_not measured yet_`. The measured runs
  were rate-limited by the generator, so they measure latency at a fixed low arrival rate only.
- **p99 latency** per engine — `_not measured yet_`. p50 and p95 for both engines are recorded in
  [`measured-results.md`](measured-results.md); the probe numbers on the System Intelligence panel are
  a handful of single requests and are not a percentile distribution.
- **Flink vs Spark comparison** — measured, but **not plotted**. The numbers (500/500 decision
  agreement, e2e p50 92 ms vs 3862 ms, run `r_d48339d70bb9ceb4`) are in
  [`measured-results.md`](measured-results.md); no figure in this directory draws them yet.
- **Cost figures in money.** Cloud usage is drawn from Free Trial credit; credit consumption is not
  money charged, and no figure states a currency amount.
- **A calibrated probability.** The calibration figure is included precisely to show the score is
  not one; it is a ranking score with fixed thresholds.

## Caveat on the CA2 latency numbers

The recovery timeline and the probe tiles report wall-clock values observed once, on the
`fraudwatch-pipeline` VM, on 2026-09-18. The `e2e_ms` figure is a **producer-to-database**
measurement — it includes the producer, Kafka, the Flink job, the scoring call and the PostgreSQL
write, and it is not a Flink-internal processing latency. Treat both figures as evidence that the
mechanism works, not as a benchmark.
